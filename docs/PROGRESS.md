## 一、项目概述

「时光邮局」是一个会记住你生活的 AI 伙伴。用户用照片、语音、日记记录生活，AI 通过追问补全当天的经历，逐步形成对用户的长期记忆，并生成故事卡片、月度回忆；在未来的某个时刻，AI 会主动以「过去的你」「未来的你」或「时光邮差」的口吻给用户来信。

**核心闭环：** 记录 → AI 追问 → 记忆抽取 → 长期记忆 / 画像 → 邮差引擎主动来信 → 用户回信 → 回信再成为记忆

## 三、功能列表

### 1. 生活记录
- **照片**：点击或拖拽上传；自动读取 EXIF 拍摄时间与 GPS；GPS 离线解析为城市 / 景点（如「洱海」）；大图前端压缩到长边 1600px；配置视觉模型后自动生成画面描述
- **语音**：MediaRecorder 录音 + 实时音频波形；Web Speech API 边说边转文字；可选服务端转写
- **日记**：自由文本，可补充时间、地点

### 2. AI 追问
- 寄出记录后，AI 像朋友一样追问 2~3 轮（谁、在哪、那一刻的感受、为什么重要）
- 流式逐字输出
- 追问前先检索相关旧记忆，自然提起「这让我想起 X 月 X 日你说过……」，并在界面上展示联想到的记忆及其检索得分
- 支持随时「就聊到这」提前结束

### 3. 记忆系统
- 一条记录自动抽取 2~6 条结构化记忆：经历 / 事实 / 人物 / 地点 / 心愿 / 计划 / 喜好
- 每条记忆带重要度（1~10），计划类带到期日（如「下周考试」→ 自动推算日期）
- 自动识别情绪效价与情绪词
- 记忆完成后展示「我记住了」，用户可点 × 让 AI 忘掉某条
- 人物、地点、主题自动合并成实体图谱
- 用户画像（AI 眼中的你）随记录持续更新

### 4. 邮差引擎（主动来信）
| 触发器 | 条件 | 寄信人 |
| --- | --- | --- |
| 周年回顾 | 重要记录 / 照片满 30、90、180、365 天 | 时光邮差 / 过去的你 |
| 未完结线索 | 计划、考试到期且未被回答 | 过去的你 |
| 情绪关怀 | 近 7 天情绪均值偏低 | 未来的你（同时找回一段明亮的旧记忆） |
| 里程碑 | 记录数达标；某个人出现 ≥ 4 次 | 时光邮差 |
| 时间胶囊 | 用户设定的送达日 | 从前的你 |

- 每封信可展开「为什么收到这封信」，列出触发原因与引用的真实回忆，可点回原记录
- 打开页面时自动巡检一次；信箱页可手动「请邮差现在巡检」

### 5. 信箱
- 信封列表（未读标记、邮票区分寄信人）、拆信仪式（火漆 → 翻盖 → 抽信 → 逐字浮现）、横线信纸 + 楷体正文 + 邮戳
- 核查徽章、带虚线的句子可查看出处原文；朗读（TTS 优先，退回浏览器并逐句高亮）
- 回信：回信自动成为一条新记录并进入记忆；回复「计划到期」类来信会把该计划标记为已解决
- 时间胶囊：写给一个月 / 半年 / 一年 / 三年后的自己，「正在路上的信」显示送达进度

### 6. 故事卡片
- 每条记录完成后自动生成：标题 + 120~180 字小说片段 + 一句金句
- 四种模板按内容自动选择：明信片（照片）、胶片（高兴）、信纸（日常）、夜空（低落 / 深夜）
- 一键导出 PNG，可重新生成

### 7. 时间线与月度回忆
- 时间线：按月瀑布流，人物 / 地点标签筛选，每月一条情绪色条
- 月度回忆：标题与关键词、记录统计、情绪天气曲线、3 个高光时刻、常出现的人 / 去过的地方、月度叙事、给下个月的一句话；可导出分享长图

### 8. 记忆宫殿
- AI 眼中的你：画像摘要 + 性格标签，可手动刷新
- 文风指纹：平均句长、口头禅、句尾语气词、感叹 / 省略比例、高频词、代表性原句
- 关系图谱：力导向图，节点大小代表出现频次，点击跳转到相关时间线
- 全部记忆：按类型筛选，显示被想起次数、到期状态，可编辑、可删除

### 9. 时光机与演示
- 虚拟时钟：快进 1 / 7 / 30 / 90 天，立即触发邮差巡检；全屏过场里逐条展示每个候选的去向、写信四个阶段的耗时和执行方式，可跳过动画，可一键回到真实时间
- 示例人生「林小满」：在杭州做设计师的半年，含大理旅行、妈妈、好友、胶片摄影、认证考试、近期工作压力等完整故事线
  - 刚载入：最近一周情绪低落 → 收到「未来的你」的信
  - 快进 7 天：大理旅行满三个月回顾信 + 考试到期追问信 + 时间胶囊送达

### 10. 设置与数据
- 修改称呼；体检面板：各 AI 能力的配置、最近 30 次调用的执行方式与降级原因、一键测连通
- 载入 / 清空示例数据；一键导出全部数据（JSON）
- 「它是怎么工作的」架构说明页

## 五、有价值的技术点

### 1. 分层长期记忆
原始记录 → LLM 结构化抽取 → 向量 + 实体图谱 → 持续演化的用户画像。让 AI 真正「越用越懂你」，而不是每次对话从零开始。
代码：`src/lib/memory/extract.ts`、`src/lib/memory/profile.ts`

### 2. 混合记忆检索（参考 Generative Agents）
```
score = 1.0·语义相似 + 0.35·时间衰减(半衰期45天) + 0.45·重要度 + 0.5·实体重合
```
再用 MMR（最大边际相关）去重，避免相似记忆挤满上下文。回顾往事时切换为「怀旧权重」，弱化新近性、强化重要度。每次被检索会累计 `recallCount`。
代码：`src/lib/memory/rank.ts`、`src/lib/memory/retrieve.ts`

### 3. 主动式 AI：邮差引擎
从「用户问、AI 答」变为「AI 在合适的时候主动来信」。纯函数触发器（易测试）→ 优先级排序 → 20 小时频控 → 去重键防止重复 → 检索 → 生成 → 自检 → 投递。
代码：`src/lib/postman/triggers.ts`、`src/lib/postman/engine.ts`

### 4. 个性化口吻：文风指纹
本地统计用户的句长、口头禅、语气词、标点习惯和代表性原句，转成写作指令，让「过去 / 未来的你」写信时像用户本人。「过去的你」只能检索到写信那天之前的记忆，保证时间线一致。
代码：`src/lib/memory/style.ts`

### 5. 防编造与可解释
- 信中引用的记忆 id 强校验，不存在的引用被剔除
- 接入真实模型时，再做一轮事实核查，发现无依据的说法自动改写
- 每封信公开触发原因与引用的回忆
- 用户可查看、修改、删除任何记忆，数据可完整导出

### 6. 可靠的结构化输出
LLM 输出 → 容错解析（代码块、前后废话、尾逗号、中文引号）→ zod 校验 → 失败时把错误反馈给模型修复重试 → 最终兜底。
代码：`src/lib/ai/json.ts`

### 7. 可插拔模型 + 优雅降级
对话 / 看图 / 向量 / 语音按角色独立配置，统一 OpenAI 兼容协议，可在 DeepSeek、通义千问、硅基流动等之间切换。任何一环未配置或失败都回退到本地实现：
- 对话 → 规则抽取器 + 模板写信器（会利用真实记忆和文风指纹，不是写死的台词）
- 看图 → EXIF + 用户文字
- 向量 → 本地中文 n-gram 哈希向量（零依赖、离线可用）

代码：`src/lib/ai/provider.ts`、`src/lib/ai/mock.ts`、`src/lib/memory/embed-lite.ts`、`src/lib/memory/heuristics.ts`

### 8. 流式交互与多模态采集
SSE 流式追问（先推送联想记忆元数据，再推送文本增量）；照片 EXIF 与离线逆地理编码；录音实时波形与语音转写；前端图片压缩。
代码：`src/app/api/entries/[id]/interview/route.ts`、`src/lib/geo.ts`、`src/components/record/`

### 9. 虚拟时钟
所有业务逻辑都通过统一的 `now()` 获取时间，偏移量持久化，使「几个月后」的功能可当场演示与测试。
代码：`src/lib/clock.ts`

## 七、已知限制

- 演示模式下信件与故事卡片由模板拼接，文笔不如真实大模型，正式展示建议接入 DeepSeek
- 规则抽取器对复杂句式的人名识别有限
- Web Speech API 在部分浏览器 / 网络环境下不可用，此时需配置服务端 ASR 或手动输入
- 当前为单用户本地应用，无账号体系
- 向量检索在内存中计算，适合个人数据量；数据量变大时可替换为 sqlite-vec
- 任务、邮差队列、体检记录都是进程内状态，适合单机部署；服务重启后未完成的收进邮局任务需要再点一次重试
- 新建记忆会清掉全部月度回忆缓存（保守策略），接真实模型后打开其他月份的回忆会重新生成一次
- 开发模式（`npm run dev`）每个页面首次打开要现场编译 2～5 秒，演示请用 `npm run build && npm start`
- **人工更正过的计划，回信不会把它关闭**：记忆模块的约定是自动流程只改 `userEdited=false` 的记忆，回信判断也遵守这条（`src/app/api/letters/[id]/route.ts`，有测试覆盖）。所以用户在记忆宫殿里改过某条计划（哪怕只改了重要程度）后，再回复「考完了」，这条计划仍保持未完成，回信框会提示「邮差知道这件事还没结束」。是否对「用户本人回信」放宽这条约定，待负责记忆模块的同学决定
- 真实模型写信时初稿偶尔带有记忆里找不到依据的细节（三轮测试 9 封里 4 封需要改写），核查和改写流程能兜住，最终都标为「改写过」；写信提示词还有调优空间
