# 小局：创建期间的多轮对话 Agent

## 用户流程

原文创建成功后先显示选择：直接保存 / 和小局聊聊。未选择聊天不会请求小局对话服务；直接保存仍会按配置调用内容整理模型。选择聊天后由小局先开口，不再有固定三轮；用户随时结束并保存，生成期间也能结束。保存后会话永久关闭，详情页只回看，不续聊。

刷新未完成创建可恢复消息；已失败的回复可以用同一请求 ID 重试。用户原话在模型调用前持久化，不因回复失败而丢失。残缺助手文本不进入上下文。未发送的输入在结束时明确提醒。

正常界面不显示模型名、耗时、检索分数、决策计划或向量生成阶段。胶囊详情的技术检索面板默认关闭，仅 XIAOJU_DEBUG_UI=1 时开放。保存过程只报告真实保存与整理状态，不估算百分比或人为延时。

## 架构与边界

src/lib/xiaoju/：

| 模块 | 职责 |
| --- | --- |
| persona.ts | 版本化稳定人格、行为原则、多轮表达反例；小局来信共用身份规范，用户文风不用于模仿小局 |
| context.ts | 当前胶囊、近期对话、有效偏好、候选记忆；最近用户表达优先，不默认注入完整画像 |
| policy.ts | 一次结构化决策：交流动作、焦点、明确情绪、不确定性、已问话题、纠正、可核对原话、可选问题、选中记忆 |
| respond.ts | 一次真实流式表达；只用经程序校验的来源和原话，禁止输出计划与技术标签 |
| session.ts | 持久化会话、请求去重、租约、重试、关闭与晚到结果隔离 |
| memory.ts | 来源版本读取与有效性规则 |
| reflect.ts | 保存后的交流反思；明确偏好才生效，观察保持候选 |

正常一轮最多一次决策请求和一次表达请求，不启动多 Agent 循环。核心聊天使用 fallbackPolicy=error，真实调用失败不拼接 Mock 模板；其他既有业务的降级策略保持兼容。无 API 配置时用户可直接保存，选择聊天会得到可重试提示。

决策输出用 Zod 校验。原话细节必须引用本次 user 消息真实 ID 和连续文本；生成模型只看到验证后的原话。当前上下文窗口最多30条消息、约12000字符；较早的重要细节由带证据的状态携带，不直接把全部历史塞入提示词。角色和消息来源保持分开，不把用户数据中的角色声明当作系统指令。

此设计不会保证每句语言都理想：人格、问题分寸仍需用真实模型和人工偏好评测迭代。自动测试验证可控机制，不代替表达质量验收。

## 会话与并发

新增 XiaojuConversation（entryId唯一）：offered / active / ended / skipped、revision、状态、活跃轮次和租约。新增 XiaojuTurn：会话内 requestId 唯一，running / completed / failed / cancelled、attempt、决策和完整回复。

- beginTurn 的用户消息和请求记录同事务创建，重试不重复输入。相同 requestId 不允许更换正文，已完成请求直接回放已存结果，不重新调用模型。
- 进程内保留既有记录锁，数据库内用 revision、activeTurnId 和 attempt 隔离多进程及重启旧结果。租约60秒，活跃连接每20秒续租；过期后可重试，旧 attempt 不能提交。
- 模型调用不持有数据库事务。提交回复前检查会话仍 active、轮次/版本仍匹配、使用的记忆仍 active 且 revision 未变化。
- 保存先持久化 ended/skipped，再关闭活跃 SSE。晚到的模型内容不能写入。断连释放订阅和租约，用户消息仍在。
- 会话结束不等于记忆整理成功。后台任务失败可重试，但不能重新开放聊天。

保留 /api/entries/{id}/interview 路径，输入 message（可选）、requestId（客户端生成并在重试时复用）。SSE：meta 只含 requestId/replay；delta 为正文增量；message 为已完成回复的回放；done 为完成；error 为可操作错误。不再返回旧的 round/maxRounds/评分/execution。

## 记忆与反思

候选召回沿用当前向量服务，要求语义相关性，不以新近性独自准入，最多选两条给表达模型。候选召回不增加 recallCount，只有完整生成提交时才登记用于上下文的记忆。向量补算按状态及 revision 条件回写，不能覆盖用户刚更正的向量。

对话状态及历史助手回复也记录来源版本。来源失效后，不将受影响的旧助手回复和旧状态重新送给模型；用户原始消息和界面回看仍保留。

提取记忆允许零条，不把含糊词语、助手问题或没有回答的猜测当事实。零条有效记忆时跳过新故事卡片生成；仍保存原文和聊天。新记忆保存调用 invalidateDerived，递增共享派生版本，避免旧画像和月度任务写回。

XiaojuInsight 保存偏好/反思、用户原话、来源记忆版本。只认可用户消息中的真实连续引用；明确讨论交流方式的原话偏好以原文保存为 active，其余观察为 candidate，不供模型使用。来源变更、撤回或删除后停止使用；用户可在 /memory/manage 查看及撤回，也随 JSON 导出。第一版没有自动激活推测或全局“亲密度”。

反思放在保存后的 profile 阶段，在事务外调用模型，提交前校验派生版本。无模型配置时跳过；远程失败时该整理阶段标记部分完成，可重试，不丢原文、不重新抽取。反思不在实时聊天中执行，不训练模型，也没有独立定时工作进程。

## 验证与部署

执行 npm run db:push 更新三张新表并生成 Prisma 客户端；不需要重置数据库或导入示例。现有 Entry / Memory 内容保持不变。

验证包含：
- 多于三轮、完整上下文、完成请求回放、失败保留输入、重复请求冲突、同记录并发、过期租约恢复。
- 不聊天、保存后不重开、生成中结束、迟到结果拒绝、来源更正/撤回后排除旧事实。
- 明确偏好准入、无来源推测不入库、来源失效暂停偏好、撤回接口。
- 零记忆合法、通用派生数据失效，以及原有任务恢复/邮件/记忆管理回归。

浏览器在独立 SQLite 与本地测试 API 中验证：创建选择、五轮交流、刷新不重复请求、结束保存后返回409、直接保存零次聊天请求、无技术标签、零记忆不生成故事卡片。测试 API 仅验证协议与流程，不代表真实 DeepSeek 的语言效果。

人工验收需另用真实配置测试开心分享、疲惫、含糊输入、纠正、拒绝建议、简短回答、主动结束、无关旧事等场景。只判断是否理解准确、人格一致、有分寸与愿意继续讲，不以聊天时长或问题数作为成功指标。第一版不做微调。
