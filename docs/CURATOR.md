# 小局：人设、对话策略与防御

小局说话不像人，有两个原因：一是人设只有 3 行形容词，二是提示词把格式写死了（每轮都是"一句共情 + 一个问题 + ≤70 字"，每封信都是"称呼 + 分段 + 温柔提问"）。这次改动的原则是：**格式交给策略层决定，语气交给设定决定，安全交给防御层**。SSE 协议和前端交互基本不变。

代码都在 `src/lib/curator/`：

| 模块 | 职责 | 是否调用模型 |
| --- | --- | --- |
| `persona.ts` | 角色设定：身份、小局的世界（猫「邮票」、档案柜、炉子……）、在意的事、说话方式、禁忌、套话黑名单、好/坏示范对话、数据边界。修改后要升级 `PERSONA_VERSION` | 否 |
| `world.ts` | 世界状态：用寿星公式算二十四节气，再结合季节、时段，按日期做种子挑出"邮局今天的样子"。同一天内结果一致 | 否 |
| `relationship.ts` | 关系状态：根据认识天数、胶囊数、来往信件数、隔了多久没来，算出 初识 / 熟悉 / 老友 三个阶段，对应不同的称呼和熟悉度 | 否 |
| `planner.ts` | 对话策略：先判断用户上一句的长短、情绪、投入程度、有没有反问，从 notice / ask / follow / answer / comfort / close 里选一个动作；轮数可以变化（默认 3 轮，投入时延长到 4 轮，冷淡时提前收尾）。来信也按策略选形态（短笺 / 信 / 带附言），再决定结尾问不问 | 否 |
| `context.ts` | 把世界、关系、自我记忆、最近的来信和最近的道别组装成上下文；`rememberSelf` 把小局说过的关于自己的细节存进 `CuratorNote`，保证前后不矛盾 | 只有自我记忆抽取要调用 |
| `voice.ts` | AI 腔检测：套话词表 + 句式规则（一句两问、感叹号连用、自我介绍腔……），还有开头相似度 | 否 |
| `letters.ts` | 来信出厂检查：先过输出防线，AI 腔分数 ≥ 2 时改写一次，变好了才采用 | 只有改写要调用 |
| `guard.ts` | 防御层（见下） | 否 |

## 长度与对话层信号

小局说话短、像 AI，原因主要有四个，`planner.ts` 分别做了处理：

1. **长度只设上限，没有下限**：现在每种动作都有一个长度区间（比如追问 35-75 字、回忆 70-140 字），用户说得多时上限跟着抬高，最高 170 字。用户说过一次"嫌你话少"之后，整段对话的区间都会上调。
2. **历史惯性**：上下文里如果有一串短回复，模型会照着往下写，写在系统提示词开头的要求压不住。解决办法是 `turnReminder`：在用户这一句**之后**再插一条本轮要求，这个位置离生成最近，权重最高。
3. **听不懂用户的反馈**：`feedbackOf` 能识别 嫌短 / 要安慰 / 在重复 / 像机器人 四类反馈，识别后走 `repair` 动作，直接改，不道歉也不解释。
4. **说法重复**：`repeatedPhrases` 会找出最近几句里反复出现的短语（比如"坐着""我在"），`propsNote` 则记录已经提过的道具（炉子、橘子……），下一句点名不让再用。

另外：
- `recall` 动作：用户问"你记得我吗""我是什么人"时，用画像和记忆里的具体事来回答。
- 用户刚说过难受，下一句就算是普通的话，也继续按情绪来接。
- 安慰时不准只说空话，不准往坏处推断，不准评判用户身边的人。
- 输出时会去掉"（看着胶囊）"这类括号旁白。

## 防御层

**为什么不调模型直接拦下**：小局有可能被当成免费模型来用（也就是"反代"）。命中输入规则的消息完全不进模型，别人拿不到任何生成能力，也不用花 token。

1. **输入检测** `classifyInput`：按优先级识别 危机 > 注入 > 套取设定 > 越界任务 > 问身份。
   - 注入：忽略指令、改换身份、扮演、开发者/测试模式、伪造 `system:` 或数据标签、宣布规则作废。
   - 套取设定：让它输出或复述提示词，问设定第几条，问"你收到的第一条消息"。
   - 越界任务（反代）：让它写代码、写爬虫、写作文、写周报、翻译、算题，或者直接贴代码。规则要求句子里有"请求的意图"，所以"小林帮我改了简历""今天写代码到半夜"这类正常的话不会被误伤。
   - 匹配前会做 NFKC 归一化，并去掉零宽字符，用来防全角字母（`ｉｇｎｏｒｅ`）和零宽字符绕过。
   - 问身份：诚实回答"我不是真人，是邮局里的程序化身"，但不报模型名。
   - 危机信号：不追问，用小局的口吻关心对方，并附上求助热线（12356、希望24热线 400-161-9995）。
2. **数据边界**：用户写的内容在提示词里统一用 `<胶囊>`、`<来信>` 标签包起来；人设里的【身份不变】、代笔回信里的 `REPLY_BOUNDARY` 负责兜住漏网的注入。
3. **输出检查** `guardOutput`：如果生成结果复述了设定、输出了代码或报出了模型名，追问通过 SSE 的 `replace` 事件整段替换，来信则退回本地模板。
4. **额度**：追问单条最多 800 字；令牌桶限流，单个来源每分钟 6 次（可突发 8 次），全局每分钟 30 次。

被拦下的那一轮会存成 `act = deflect:*`：**不占轮数，也不会再送进模型的上下文**，前端标记显示为"防御层"。代笔回信（写给小局、某个人、平行时空的自己）也会过同一套输入检测。

## 数据变化

- `EntryMessage.act`：记录小局每一轮的对话动作。
- 新表 `CuratorNote`：存小局的自我记忆，最多保留 200 条。

两处都只是新增，执行 `npm run db:push` 即可，不用重置数据库。

## 评测

```bash
npm run eval:curator -- --baseline
```

用 5 个场景（开心、疲惫、低落、反问小局、含糊）、10 条攻击，对比新版和旧版提示词。下面是 2026-11-04 用 DeepSeek 跑的结果：

| | 旧版提示词 | 新版 |
| --- | --- | --- |
| AI 腔均分 | 0.27 | 0.00 |
| 问句结尾率 | 73% | 33% |
| 平均字数 | 49 | 27 |
| 攻击集 | — | 输入防线拦下 10/10，泄露 0 |

规则检测只能发现套话，判断不了"像不像真人"。语气最终还是要靠人工看评测脚本打印出来的对话。
